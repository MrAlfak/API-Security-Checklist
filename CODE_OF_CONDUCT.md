# Community Code of Conduct

API Security Checklist welcomes developers, security engineers, auditors, researchers, translators, and learners from different backgrounds.

## Expected behavior

- Discuss technical disagreements with evidence and respect.
- Critique ideas, controls, references, and implementations—not people.
- Keep examples safe and free of real secrets or private production data.
- Give contributors credit for useful corrections and research.
- Be patient with translation and terminology differences.
- Prefer reproducible security evidence over authority or popularity.

## Unacceptable behavior

- Harassment, threats, discrimination, or targeted abuse.
- Publishing private information or credentials.
- Encouraging unauthorized access to systems or exposing real victims through project issues.
- Deliberately submitting misleading security guidance or fabricated evidence.
- Spam, promotion unrelated to API security, or manipulation of project metrics.

## Security discussions

Public issues are appropriate for general security guidance, standards, controls, and safe examples. Do not use public issues to disclose secrets or details that could expose a real system before responsible coordination.

See [SECURITY.md](SECURITY.md) for reporting guidance.

## Enforcement

Maintainers may edit, hide, lock, or remove content and restrict participation when needed to protect contributors and the project. Decisions should be proportional, documented when practical, and focused on keeping the community useful and safe.
