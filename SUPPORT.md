# Support

Thanks for using API Security Checklist.

## Questions and usage help

For questions about how to apply a control, open a GitHub issue and include:

- the relevant control ID,
- API type/scope,
- the security behavior you are trying to verify,
- a minimal non-sensitive example,
- what is unclear in the current guidance.

## Suggesting a new control or standard update

Use the dedicated issue templates. Strong proposals include an authoritative source and at least one concrete verification idea.

## Reporting a documentation or translation problem

Open an issue with the affected file/control ID and the suggested correction. Persian terminology improvements are welcome.

## Security vulnerabilities

Do **not** disclose a vulnerability in a real system, secret, credential, private endpoint, or sensitive production information in a public issue.

Follow [SECURITY.md](SECURITY.md) for security-reporting guidance.

## Project support

The most useful ways to support this open-source project are:

1. ⭐ Star the repository if it saves you time.
2. Share it with backend, AppSec, DevSecOps, and penetration-testing teams.
3. Report outdated or ambiguous guidance.
4. Contribute verification steps, mappings, translations, and secure examples.
5. Reference the project in internal security standards where it is useful.

A larger community makes security guidance easier to review and keep current.
